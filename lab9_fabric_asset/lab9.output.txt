=== Task 2: create + query asset ===
  1. PROPOSAL     client -> ['peer0.org1', 'peer0.org2']: CreateAsset('asset1', 'blue', '5', 'Tomoko')
  2. ENDORSEMENT  2 signed responses; rwset = {"reads": {"asset1": 0}, "writes": {"asset1": {"ID": "asset1", "color": "blue", "size": 5, "owner": "Tomoko"}}}
  3. ORDERING     orderer cut block #0 with 1 tx (no chaincode executed)
  4. VALIDATION   peer0.org1: [('tx001', 'VALID')]
  4. VALIDATION   peer0.org2: [('tx001', 'VALID')]
  5. COMMIT       block #0 appended on all peers; world state updated for VALID txs
  Query asset1 on peer0.org2: {'ID': 'asset1', 'color': 'blue', 'size': 5, 'owner': 'Tomoko'}

=== Task 4c: tampered endorsement is rejected ===
  result: [('tx006', 'ENDORSEMENT_MISMATCH')] (tampered endorsement disagrees with the other peer; its signature would also fail)

Transaction path: Proposal -> Endorsement (peers execute chaincode, sign rwset) ->
Ordering (orderer sequences txs into blocks, never executes them) -> Validation
(each peer checks endorsement policy + MVCC versions) -> Commit (block appended,
world state updated only for VALID txs; invalid txs stay on the ledger flagged).
